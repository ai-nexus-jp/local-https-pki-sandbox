# Step 0: 事前準備とプロジェクト構成の理解

このステップでは、証明書の学習・検証を始める前に「プロジェクト構成のベストプラクティス」と「実行環境の準備」を確認します。

## 1. なぜ証明書を専用フォルダで管理するのか？

実務や開発プロジェクトで証明書・TLS通信を検証する場合、プロジェクトルート直下に専用ディレクトリを切って管理するのが一般的です。

| フォルダ名 | よく使われる文脈 |
| :--- | :--- |
| `certs/` | **最も一般的・推奨**（"Certificates" の略。Docker / Node.js / Go / Python 等） |
| `ssl/` または `tls/` | Nginx / Apache などのWebサーバー設定とセットで管理する場合 |
| `pki/` | ルートCA・中間CA・CSR・CRL など公開鍵基盤全体の構成を検証する場合 |

このチュートリアルでは `certs/` ディレクトリにすべての生成ファイル（鍵・証明書・CSRなど）を集約します。

### 必須のセキュリティ対策（`.gitignore`）

プロジェクト内に証明書や秘密鍵を配置する際は、**秘密鍵（`*.key` や `*.pem`）を誤って Git リポジトリにコミットしないこと**が最重要です。
このプロジェクトの `.gitignore` には以下がすでに設定されています。

```gitignore
certs/
*.key
*.pem
*.crt
*.csr
*.der
*.srl
```

## 2. 発行パターンの全体像（自己署名 vs 公的CA）

デジタル証明書は、実運用における「信頼性」と「用途」の観点から大きく2つに分かれます。

1. **自分で署名して発行する（自己署名証明書 / プライベートCA）**
   - 用途: ローカル開発・テスト、自宅サーバー、社内ネットワーク
   - 特徴: OSやブラウザの「信頼されたルート認証局リスト」に入っていないため、そのまま使うと警告画面が出る。警告を消すには端末へルート証明書を登録する。
2. **公的な認証局から発行してもらう（Let's Encrypt など）**
   - 用途: 独自ドメインを取得して一般公開する Web サイト・API サーバー
   - 特徴: ACME プロトコル等でドメイン所有権を確認して無料発行でき、世界中のブラウザから最初から信頼される。

このチュートリアルでは、仕組みを深く理解するために **1（自己署名 → プライベートCA）** を徹底的に実践します。

## 3. 環境チェックと作業用ディレクトリの作成

### 3.1 ツールの確認

プロジェクトルートで以下を実行します。

```bash
./scripts/check_env.sh
```

- **Step 1〜4** では `openssl`、`python3`、`curl` が `[OK]` であれば進められます。
- **Step 5**（ホストを汚さない隔離環境での信頼ストア登録・ブラウザ確認）では `docker` / `docker compose` を使用します。

### 3.2 `certs/` ディレクトリの作成

生成物を格納する `certs/` ディレクトリを作成します。

```bash
mkdir -p certs
```

> **メモ**: すでにプロジェクトルート直下に練習用の `cert.crt` 等がある場合でも、このチュートリアルではすべて `certs/` 配下（例: `certs/cert.crt`）で進めるため混在しません。
